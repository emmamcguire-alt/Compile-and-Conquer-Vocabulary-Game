How I Built
Compile & Conquer

01 — The Concept

I wanted to make vocab review feel less like a worksheet and more like a game you actually want to play. The idea was to create a CS-themed quiz where the aesthetic itself reinforces the subject — terminal windows, monospace fonts, amber glows, and scanlines that make you feel like you're inside a computer.

The name "Compile & Conquer" came naturally — in programming, compiling is the final step where your code either works or it doesn't. That felt like the perfect win metaphor: answer enough questions correctly and you "compile" successfully.

02 — Structure & Design

The entire game lives in a single HTML file — no external frameworks, no JavaScript libraries, no build tools. Just HTML, CSS, and vanilla JS working together. Here's the high-level structure:

index.html ├── <style> — All styling with CSS variables ├── <body> — Start screen, game area, end screen │ ├── Header (title, creator credit) │ ├── Instructions panel │ ├── HUD bar (score, progress, question #) │ ├── Question card (dynamic content) │ ├── Answer choices (4-button grid) │ ├── Feedback bar (correct/wrong flash) │ └── End screen (win or lose state) └── <script> — All game logic
03 — The Vocabulary Data

Fifteen CS terms are stored as a JavaScript array of objects. Each game draws 10 randomly. Each entry has a term and its definition. The game generates questions in both directions — sometimes showing the term and asking for the definition, sometimes showing the definition and asking for the term. This doubles the challenge without needing more vocab words.

const vocab = [ { term: "Algorithm", def: "A step-by-step set of instructions..." }, { term: "Assignment Operator", def: "The = symbol that stores a value..." }, // ... and so on ];
04 — Quiz Logic

When a game starts, the question pool gets shuffled using a Fisher-Yates shuffle algorithm. Each question randomly decides whether to show the TERM (pick the definition) or the DEFINITION (pick the term). Wrong answer choices are also randomly pulled from the remaining vocab so they're always plausible distractors.

  • Questions are shuffled so no two games are identical
  • Correct answer position is randomized in the 4-choice grid
  • Win condition: ≥ 10 out of 12 correct triggers the success screen
  • CSS animations handle visual feedback (glow, shake, color flash)
05 — Visual Design Choices

The aesthetic is "retro terminal meets arcade leaderboard." The scanline overlay (a CSS repeating gradient) gives a CRT monitor feel. The amber color palette is a direct reference to vintage amber phosphor monitors. The green accent color references classic terminal green, and the whole thing is layered on a dark grid background for depth.

Fonts used: Orbitron for display headings (a geometric sci-fi typeface), Share Tech Mono for code-style labels and UI chrome, and DM Sans for body text readability.

06 — What I Learned

Building this reinforced just how much you can accomplish with pure HTML/CSS/JS — no frameworks required. CSS variables make theming incredibly maintainable. Using animation-delay for staggered effects creates polish without complexity. And keeping all state in simple JavaScript variables (score, currentQ, etc.) is all you need for a small game like this.
